续跑指纹：改为启动时算一次，并修正一处会导致跨树拼接的实现

1) 指纹只在启动时算一次（FP_NOW），不再每步重算。
   实测代价：文件系统抖动时 git diff 会因索引整体刷新而挂起，套 timeout
   20 也照样被拖满（连续两次 RC=124）；而它原本在 ckpt_mark 里每步调用，
   55 步就是十几分钟纯卡顿。按次计算不削弱判据：新分段在自己启动时算一次，
   与上一段 checkpoint 记录的指纹比对，树变了照样判不符；反而更稳——变异
   审计会在运行中改写源码再还原，逐步指纹可能记下还原后不复现的值。

2) 曾试图用 diff-index 提速，实测证伪：索引 stat 缓存被文件系统重挂整体
   失效后，它报 548 个改动而实际只有 1 个，指纹与内容无关且会随索引是否被
   刷新而漂移。已改回 porcelain 的 git diff，正确性优先。

验证（四例，含正向对照）：
   T1  指纹一致       -> 自动接管（证明不是恒拒）
   T2  指纹不符       -> 丢弃并从头开始
   T3  两边均不可得   -> 拒绝拼接（旧实现此处等号成立会照常接管）
   T4  仅 checkpoint 哨兵 -> 拒绝拼接
